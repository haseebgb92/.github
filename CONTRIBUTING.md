# Contributing

Thanks for helping improve these projects.

## Before opening a pull request

1. Search existing issues and discussions.
2. For bugs, include clear reproduction steps, expected behavior, actual behavior, platform/version details and relevant logs.
3. For larger features, open an issue first so we can agree on scope before substantial work begins.
4. Keep pull requests focused. Avoid unrelated refactors in the same change.
5. Update documentation when behavior or setup changes.
6. Never commit credentials, API keys, tokens, customer data or private files.

## Development principles

Contributions should generally preserve these principles:

- practical over clever
- local/deterministic execution before expensive model calls where appropriate
- explicit approval for destructive or consequential actions
- clear failure states instead of pretending work succeeded
- backward compatibility where practical
- lightweight dependencies where possible

## Pull requests

Please include:

- what changed
- why it changed
- how you tested it
- screenshots for visible UI changes
- any migration or compatibility notes

Small, well-tested pull requests are easier to review and merge.

## Good first contributions

Documentation fixes, reproducible bug reports, platform compatibility fixes, test coverage, packaging improvements and narrowly scoped integrations are all welcome.
